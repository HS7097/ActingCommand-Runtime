# Restore a resource draft from Lab evidence

`actinglab --json resource restore --repo <new directory> --state-root <Runtime state> --request-id <ID> --through-sequence <fixed upper bound> --zip <original package> --expected-sha256 <external hash> --task-id <draft ID>` reads the native GlobalLedger snapshot and ArtifactStore through their existing read-only interfaces. Repeat `--request-id` for 1–32 unique requests from the same instance and package. Each identity query uses pages of 256 events, bounded to 4096 events; incomplete, conflicting or oversized evidence fails explicitly. Native snapshot opening retains its existing prefix semantics; on an SQLite root each artifact is verified separately (Workflow #375 R5b). A request whose frame or record file does not exist (deleted by hand) is skipped and listed as a gap `material_missing` with its `artifact_ids`; any other artifact failure still fails the restore.

For a content directory, use `--package <original package directory> --package-ref <versioned JSON>`; the complete [package reference](package-reference.md) must agree with the recorded Lab evidence. Evidence recorded with a Git source-tree reference is refused with `source_tree_loader_retired`, since that loader is retired. Containment verifies the supplied package identity before exposing metadata and original source entries. Online RuntimeClient and this offline adapter share the contract's pure Lab evidence consistency checks. The client retains receipt/request authentication, artifact I/O and fatal latching. The offline reader uses native command terminals and the actual event, artifact, frame, recognition, lease, input action and outcome identities. No device/provider or daemon is initialized by restore.

The output uses the existing 0.6 Operation Bundle, projection metadata and `AuthoringDraft`. It contains `ours/operations/<task>/task.json`, the necessary original template assets, `ours/operations/resources.json` and `ours/navigation/<game>.<server>.projection.json`. Materialization claims a new directory and uses the original authoring path/scope protection. Source entry paths and SHA-256 values remain in provenance. Copied template assets use their byte hash as the local filename. Original frames and private facts/value/detail remain in their controlled evidence location.

Only a verified InputCommitted with actual before/after pages and expressible Tap/Swipe geometry contributes an operation. Operations are ordered by real input sequence and identified by physical action ID. Same-page inputs use `to:null` and `expect_after`; resource effects are left empty. Guards and necessary template/color/page-rule declarations come from the admitted source. Incomplete records, missing dependencies and uncertain input outcomes remain explicit provenance gaps. No placeholder input is emitted. The original empty-operation package rejection remains effective.

New action annotations default to `dangerous` with the restore classification source. An existing selected resource's classification is retained only with its actual original decision source. Personal target dependencies are withheld from the draft. An element's existing purpose can be retained; an explicit coordinate with no business meaning has an empty purpose.

`--entry-page`, repeatable `--target-page`, and `--goal` are explicit author inputs. Page values must exist in the admitted source. Omitted values remain unspecified. The command reports `draft_generated`, record and operation counts, gaps and pending author inputs. A draft without an explicit target is an unfinished navigation source.

To use the draft, review its gaps, supply the actual target/entry and action semantics, then manually transfer its source declarations and referenced assets into `packs/<package_id>/resources/`. Author `control.json` with the matching game, server, entry task, resolution and execution mode according to the [self-contained source layout](package-reference.md#self-contained-source-layout). Keep template and dependency references local to that content directory. Recognition, page, navigation and index outputs are derived in memory by the loader. Validate the source declarations with `resource validate`, obtain the admitted content identity with `package digest --package <directory>`, and generate a standard bundle with `package bundle`. Restore does not build or run the draft and does not report business completion from static admission.
