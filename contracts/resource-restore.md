# Restore a resource draft from Lab evidence

`actinglab --json resource restore --repo <new directory> --state-root <Runtime state> --request-id <ID> --through-sequence <fixed upper bound> --zip <original package> --expected-sha256 <external hash> --task-id <draft ID>` reads the native GlobalLedger snapshot and ArtifactStore through their existing read-only interfaces. Repeat `--request-id` for 1–32 unique requests from the same instance and package. Each identity query uses pages of 256 events, bounded to 4096 events; incomplete, conflicting or oversized evidence fails explicitly. Native snapshot opening retains its existing prefix and artifact validation semantics.

Containment verifies the external package hash before exposing metadata and original source entries. Online RuntimeClient and this offline adapter share the contract's pure Lab evidence consistency checks. The client retains receipt/request authentication, artifact I/O and fatal latching. The offline reader uses native command terminals and the actual event, artifact, frame, recognition, lease, input action and outcome identities. No device/provider or daemon is initialized by restore.

The output uses the existing 0.6 Operation Bundle, projection metadata and `AuthoringDraft`. It contains `ours/operations/<task>/task.json`, the necessary original template assets, `ours/operations/resources.json` and `ours/navigation/<game>.<server>.projection.json`. Materialization claims a new directory and uses the original authoring path/scope protection. Source entry paths and SHA-256 values remain in provenance. Copied template assets use their byte hash as the local filename. Original frames and private facts/value/detail remain in their controlled evidence location.

Only a verified InputCommitted with actual before/after pages and expressible Tap/Swipe geometry contributes an operation. Operations are ordered by real input sequence and identified by physical action ID. Same-page inputs use `to:null` and `expect_after`; resource effects are left empty. Guards and necessary template/color/page-rule declarations come from the admitted source. Incomplete records, missing dependencies and uncertain input outcomes remain explicit provenance gaps. No placeholder input is emitted. The original empty-operation package rejection remains effective.

New action annotations default to `dangerous` with the restore classification source. An existing selected resource's classification is retained only with its actual original decision source. Personal target dependencies are withheld from the draft. An element's existing purpose can be retained; an explicit coordinate with no business meaning has an empty purpose.

`--entry-page`, repeatable `--target-page`, and `--goal` are explicit author inputs. Page values must exist in the admitted source. Omitted values remain unspecified. The command reports `draft_generated`, record and operation counts, gaps and pending author inputs. A draft without an explicit target is an unfinished navigation source. Authors can supply an actual target and entry and then use the existing `resource convert` → `package build-task` → `package validate` commands. Build-task retains its `navigable_route` default. Restore does not build or run the draft and does not report business completion from static package validation.
